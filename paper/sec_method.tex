\section{Method}
\label{sec:method}

Fig.~\ref{fig:pipeline} shows the pipeline. Each step is one script and writes
its own result files, so a run can be stopped and resumed.

\subsection{Measuring overlap between corpora}

We compare every pair of the nine sources on the full cleaned corpora, before
sampling, at three levels.
\begin{itemize}
\item \textit{Exact raw}: MD5 of the text exactly as the model reads it.
\item \textit{Exact normalized}: MD5 of the body after lowercasing and
removing all whitespace.
\item \textit{Near duplicate}: MinHash~\cite{broder} with 128 permutations over
9-character shingles of the first 2{,}000 letters and digits of the body, with
locality sensitive hashing to shortlist candidates at a deliberately loose
threshold. Every shortlisted pair is then checked with the \emph{exact} Jaccard
similarity of the two shingle sets, and pairs at 0.8 or above count as the same
email. The MinHash estimate alone has a standard error of about 0.035 at this
threshold, which is too loose for a headline number, so it is used only to
shortlist.
\end{itemize}

We first tried 5-word shingles. They missed many copies, because the Kaggle
aggregate often deletes line breaks and glues two words together
(``cream?Isn't''). Character shingles over letters and digits ignore that.

\textit{Validating the matcher.} Overlap is our main measurement, so it gets
its own check. We take 400 random SpamAssassin emails that have no
whitespace-exact match in Kaggle, compare each one against all 17{,}505 Kaggle
emails by brute force, and compare that ground truth with what the pipeline
decided for the same emails. We also report how the counts move when the
Jaccard threshold is 0.7, 0.8 or 0.9.

\textit{Duplicates inside one corpus.} The same matcher run within a corpus
tells us how much of each evaluation subset has a near copy in the part of its
own corpus that a model would train on. This is what makes ordinary in-corpus
scores optimistic even before any cross-corpus question is asked.

\subsection{Leave one corpus out, with a control}

For each of the six corpora $T$ we train on the other five and test on $T$. We
run this three ways.
\begin{itemize}
\item \textit{raw}: the training data as it is.
\item \textit{clean}: every training email that has a near duplicate in $T$ is
removed first.
\item \textit{random}: the same \emph{number} of training emails is removed, at
random, with the class balance kept.
\end{itemize}
The third setting is the control that separates leakage from data volume.
Decontamination also shrinks the training set, so on its own a drop from raw to
clean could be explained by having less data. If the random setting stays close
to raw while clean drops, the cause is the leaked emails.

The three test-only sets and the sanitised variants are scored with a model
trained on all six corpora, again with near duplicates of the test set removed.

As a reference we report the in-corpus score two ways: the usual 80/20
stratified split inside each corpus, and, so that it can be compared with the
other model families, a model trained on the corpus minus the shared
evaluation subset and tested on that subset.

\subsection{Models}

\textit{Classical.} TF-IDF over word unigrams and bigrams (50{,}000 features,
minimum document frequency 2) with logistic regression or multinomial naive
Bayes.

\textit{Fine-tuned encoder.} \texttt{distilbert-base-uncased}~\cite{distilbert},
one epoch, 128 tokens, batch 16, learning rate $5\times10^{-5}$, on a
stratified sample of 1{,}000 emails per training corpus (about 5{,}000 per
fold), on the laptop CPU.

\textit{Small open LLMs.} Llama-3.2-1B, Llama-3.2-3B, Llama-3.1-8B,
Qwen-2.5-7B, Gemma-3-12B and Phi-4 (14B), instruction tuned, called through
OpenRouter. The system prompt asks whether the email is ``malicious or
unwanted (phishing, scam or spam) or legitimate'' and to answer with one word.
Temperature is 0 and emails are cut to 1{,}500 characters. An LLM never sees
our training data, so every test set is unseen for it.

\textit{Published phishing detectors.} Three models that other people trained
and released for this task: a BERT-large and a ModernBERT-large classifier, and
an ungated merge of Phishsense-1B~\cite{phishsense}. Their model cards name the
Kaggle set, SpamAssassin, Enron, CEAS or Ling as training data, which is the
same lineage we test on, so their scores on our legacy corpora are partly a
memory test while E-PhishLLM is mail they cannot have seen. Phishsense is a
causal model; its official prompt template sits in a gated repository we cannot
read, so we prompt it exactly like our other LLMs and say so.

\textit{Commercial reference.} Gemini-3.1-Flash-Lite and GPT-4o-mini under the
same prompt, to show how far the cheap open models are from what a paid API
gives today.

\subsection{Reading the answers}

An answer containing ``legit'' (or a negation such as ``not phishing'') counts
as negative, one containing ``phish'', ``spam'' or ``malicious'' as positive.
Some providers truncate the reply to a single token, so a prefix such as
``ph'' or ``leg'' is accepted as well. Anything else counts as no verdict, is
treated as negative and is reported separately, because in a real pipeline an
answer nobody can parse is a missed detection. Calls that failed after four
retries are recorded with zero tokens and retried on the next run, and are
counted apart from refusals. All raw answers are kept, so the parser can be
improved and the answers re-read without paying for the calls again, which is
what we did once in this study.

\subsection{Metrics}

We report F1 for the positive class, because accuracy hides the failure we
care about, and next to it the false alarm rate, the share of legitimate
emails that a model flags. The headline robustness number is the mean F1 over
the six held-out corpora. Around it we give two kinds of uncertainty: a 1{,}000
sample bootstrap over emails, using the same resample positions for every model
so that differences between models are paired, and a leave-one-corpus-out
jackknife over the six corpora, which is the wider and more honest interval
when the question is how a model behaves on a corpus nobody has seen. Paired
differences between models are tested with an exact McNemar test.

Because the evaluation subsets are balanced and real mailboxes are not, we also
report precision and F1 recomputed at lower phishing rates, keeping the
measured recall and false alarm rate fixed.

\textit{Cost.} For LLMs, cost is the sum of the charge OpenRouter reports for
every call, over the same six corpora the F1 column uses, divided by the number
of emails. It is the cost of emails truncated to 1{,}500 characters, so longer
mail costs more. Local models have no API cost; we report their processing time
instead. One caveat we cannot remove: OpenRouter routes a model to a provider of
its choosing, so a small part of the cost difference between models is routing
rather than the model itself.

\subsection{Two more protocols}

\textit{What the positives are.} An LLM annotator sorts every positive email in
the evaluation subsets into phishing or spam, with a second model annotating
300 of them so that agreement can be reported rather than assumed.

\textit{Explanation quality.} On 100 emails two models are asked for a verdict
and one sentence of reasoning, and a third model judges whether the reason
points at something that is really in the email and whether it supports the
verdict. We also read a sample by hand, because a model judging a model is not
the last word.
